\begin{frame}{研究问题}
  \begin{itemize}
    \item 现代LLM服务系统越来越容易暴露可复用的前缀或KV状态。
    \item 但\alert{可复用状态的存在}并不自动意味着\alert{端到端延迟下降}。
    \item 真正把这些状态“兑现”为收益，可能需要跨worker传输、主机到设备搬运、部分重构以及额外的元数据管理。
  \end{itemize}

  \vspace{0.5em}
  \begin{block}{核心系统问题}
    当一个请求到达时，面对已有可复用状态，系统究竟应该：
    \[
      \texttt{full\_reuse} \qquad \texttt{partial\_reuse} \qquad \texttt{recompute}
    \]
  \end{block}
\end{frame}

\begin{frame}{研究范围与论文主张}
  \begin{itemize}
    \item 本仓库只研究一个很窄的控制点：\alert{请求到达时的KV物化决策}。
    \item 不把问题扩展成调度器重写、placement策略、eviction控制或decode backend选择。
    \item placement、迁移、内存压力只作为\alert{代价模型背景变量}存在，而不是本文主体。
  \end{itemize}

  \vspace{0.5em}
  \begin{block}{论文主张}
    reuse 不是“发现了就该用”，而是一个需要被\alert{控制}的系统决策问题。
  \end{block}
\end{frame}

\begin{frame}{三动作决策面}
  \begin{itemize}
    \item \texttt{full\_reuse}：直接兑现已有前缀/KV状态。
    \item \texttt{partial\_reuse}：只复用高价值前缀段，剩余尾部重新计算。
    \item \texttt{recompute}：放弃兑现已有状态，直接重算。
  \end{itemize}

  \vspace{0.5em}
  \begin{block}{当前offline语义}
    \texttt{partial\_reuse} 已从“固定半截复用”改成\alert{切点优化问题}：
    \[
      r^* = \arg\min_r\; \bigl(\mathrm{materialization\_cost}(r) + \mathrm{recompute\_cost}(\mathrm{tail}(r))\bigr)
    \]
  \end{block}

  \begin{itemize}
    \item 这样 policy、baseline 和 oracle 共享同一套三动作含义。
  \end{itemize}
\end{frame}

\begin{frame}{什么时候别直接全复用}
  \begin{block}{核心判断}
    不是“能复用就全复用”，而是：\alert{后半段拿回来，到底还值不值。}
  \end{block}

  \begin{columns}[T]
    \begin{column}{0.49\textwidth}
      \scriptsize
      \begin{block}{\texttt{partial\_reuse} 更优}
        \begin{itemize}
          \item 前面很多内容是固定的，后面经常变
          \item 前面复用收益大，后面复用收益小
          \item 典型：固定提示词/工具框架 + 最近一轮对话或检索结果
        \end{itemize}
      \end{block}
      直觉上：\alert{只复用前面稳定的部分。}
    \end{column}
    \begin{column}{0.49\textwidth}
      \scriptsize
      \begin{block}{\texttt{recompute} 更优}
        \begin{itemize}
          \item 能复用的内容太少
          \item 这段内容变化太大，不值得搬回来
          \item 拿回来再接起来，比自己重算还贵
        \end{itemize}
      \end{block}
      直觉上：\alert{既然不划算，那就别复用。}
    \end{column}
  \end{columns}

  \vspace{0.3em}
  \begin{block}{学生版记忆法}
    大部分都稳定 $\rightarrow$ \texttt{full\_reuse}；前面稳定后面易变 $\rightarrow$ \texttt{partial\_reuse}；可复用太少或太不稳定 $\rightarrow$ \texttt{recompute}。
  \end{block}
\end{frame}

\begin{frame}{证据边界必须分开}
  \begin{columns}[T]
    \begin{column}{0.49\textwidth}
      \begin{block}{Offline决策研究}
        \begin{itemize}
          \item 解释三动作在不同工作负载下何时更优
          \item 关注决策结构、敏感性和headroom
          \item oracle 只作为上界，不作为可部署结果
        \end{itemize}
      \end{block}
    \end{column}
    \begin{column}{0.49\textwidth}
      \begin{block}{Online运行时验证}
        \begin{itemize}
          \item 检查当前插件与runtime seam到底能兑现多少
          \item 允许出现负结果或边界结果
          \item 不能把offline优势直接写成live收益
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}

  \vspace{0.5em}
  \alert{一句话：offline证明“值得控制”，live验证“当前系统能否真正做到”。}
\end{frame}

\begin{frame}{当前系统已经做到什么}
  \begin{itemize}
    \item 已完成三动作 offline policy 与 evaluator。
    \item 已接入 \texttt{llm-serving-workloads} 作为共享 workload source of truth。
    \item 已有插件侧 live control：从请求头估计信号、做决策、设置 cache salt、传递 cut point。
    \item 已在 \texttt{carrier/vllm-hust} 中推进到第二版 segmented seam：\texttt{target\_reuse\_tokens} 不仅截断 prefix-cache lookup，也会截断 shared-cache commit，并在 reuse boundary 之后重置 tail hash chain。
  \end{itemize}

  \vspace{0.5em}
  \begin{block}{当前truthfulness boundary}
    现在的online \texttt{partial\_reuse} 已能以\alert{block对齐后的segmented prefix-cache动作}执行：
    共享前缀与重算尾部已经在 carrier seam 上进入不同哈希命名空间，
    但还不是 connector-backed、exact token-level 的完整 segmented materialization path。
  \end{block}
\end{frame}

\begin{frame}{真实实验设置}
  \begin{itemize}
    \item 模型：Qwen2.5-7B-Instruct
    \item 运行环境：carrier内本地 vLLM runtime，开启 prefix caching
    \item Ascend live路径实际 block size 会固定到 \textbf{128}，因此 partial cut point 必须先做 block 对齐
    \item 本轮对比对象：
    \begin{itemize}
      \item \textbf{旧 baseline}：旧 seam，\texttt{floor=256}，\texttt{confidence\_penalty=4.0}
      \item \textbf{旧 tuned}：旧 seam，\texttt{floor=128}，\texttt{confidence\_penalty=8.0}
      \item \textbf{新 baseline}：新 segmented seam，\texttt{floor=256}，\texttt{confidence\_penalty=4.0}
      \item \textbf{新 tuned}：新 segmented seam，\texttt{floor=128}，\texttt{confidence\_penalty=8.0}
    \end{itemize}
    \item 代表场景：
    \begin{itemize}
      \item \texttt{shared\_scenario\_multi\_turn\_knowledge\_service}
      \item \texttt{shared\_tool\_scaffold\_agent}
    \end{itemize}
    \item 新增 runtime-boundary live补充验证：
    \begin{itemize}
      \item 成功跑通：\texttt{shared\_prefix\_multi\_tenant\_assistant}、\texttt{session\_continuation\_with\_maintenance}
      \item 更正后的第三个 case：\texttt{dynamic\_rag\_corpus\_update} 在使用真实 Qwen tokenizer 生成 workload 后可稳定跑通
    \end{itemize}
  \end{itemize}
\end{frame}

  \vspace{0.5em}
  \begin{alertblock}{关键更正}
    \texttt{dynamic\_rag\_corpus\_update} 之前之所以在 live 路径上报 32K 越界，不是因为 case 本身太长，而是因为我们用 \textbf{WhitespaceTokenizer} 生成 workload，导致 token budget 在真实 Qwen tokenizer 下严重失真。改成真实 tokenizer 后，这条 case 可以用原始 \texttt{72} 输出预算稳定跑通。
  \end{alertblock}

  \vspace{0.2em}
  \begin{block}{这页想说明什么}
    \begin{itemize}
      \item 这两组新增 live workload 不是 offline proxy，而是真实 Qwen2.5-7B 在线服务跑出来的结果。
      \item 其中前两个 case 的 observed/effective action 都稳定落到 \texttt{partial\_reuse}，说明新 seam 已不只是“看到 partial”，而是能把 partial 真正 materialize 出来。
      \item dynamic RAG 则补上了第三种真实 online 证据：当 retrieval overlap 在后续轮次继续增大时，系统会从首轮 \texttt{partial\_reuse} 自然切到后续轮次 \texttt{full\_reuse}。
    \end{itemize}
  \end{block}
\end{frame}

\begin{frame}{这次 rerun 到底说明了什么}
  \begin{columns}[T]
    \begin{column}{0.45\textwidth}
      \begin{block}{新的 baseline decision mix}
        \begin{itemize}
          \item knowledge-service：32 个请求里，8 个 effective \texttt{recompute}，24 个 effective \texttt{partial\_reuse}
          \item tool-scaffold：observed 64 个 \texttt{partial\_reuse}，但 effective 上变成 48 个 \texttt{partial\_reuse} + 16 个 \texttt{full\_reuse}
          \item 新增 two live boundary cases：都出现 40/40 的 effective \texttt{partial\_reuse}，说明当前 seam 已能在真实服务里稳定兑现 partial 语义
          \item 修正后的 dynamic RAG：32 个请求全部完成，effective mix 为 8 个 \texttt{partial\_reuse} + 24 个 \texttt{full\_reuse}
          \item fallback 不再只有 cut-point realign，还会出现 \texttt{block\_aligned\_partial\_reuse\_dominated\_by\_full\_reuse}
        \end{itemize}
      \end{block}
    \end{column}
    \begin{column}{0.55\textwidth}
      \small
      \begin{alertblock}{主因判断}
        \begin{enumerate}
          \item 新 segmented seam 确实把旧 tuned 的负结果拉回到了可竞争区间，这说明此前主要瓶颈在 runtime realization。
          \item dynamic RAG 的修正 rerun 说明：真实 online 失败有时并不是 policy 或模型窗口本身的问题，而是 workload token budget 是否与真实 tokenizer 对齐。
          \item 因此更合理的论文结论应是：\textbf{runtime seam、guardrail 与 workload construction fidelity 联合作用}，并且收益具有 workload dependence。
        \end{enumerate}
      \end{alertblock}
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{当前修复与边界解释}
  \begin{itemize}
    \item 已修复的一点：本地 runtime control 不再错误占用 \texttt{kv\_transfer\_params}，而是改到独立的 materialization-control payload。
    \item 已新增的一点：live \texttt{partial\_reuse} 会先按 block size 对齐，再在 \texttt{partial/full/recompute} 间重排可实现动作。
    \item 已推进的一点：carrier seam 现在不只截断 lookup 和 commit，还会在 reuse boundary 之后用 request-scoped salt 重置 tail hash chain。
    \item 这让当前 online 结果的语义更诚实：
    \begin{itemize}
      \item 它确实在测试一个 block-aligned segmented prefix-cache runtime seam；
      \item 但它还没有进入 connector-backed KV transfer/materialization 路径。
    \end{itemize}
    \item 这次四格矩阵表明：更强的 runtime seam 足以把 tuned partial 的 live 性能显著拉回，但是否超过 baseline 仍取决于 guardrail 与 workload 形态。
  \end{itemize}

  \vspace{0.5em}
  \begin{block}{更准确的结论}
    现阶段 online 结果说明的是：\alert{runtime realization 与 guardrail 共同决定收益}；更强的 seam 让 \texttt{partial\_reuse} 重新变得可竞争，但 paper claim 必须保持 workload-dependent。
  \end{block}
\end{frame}

\begin{frame}{下一步工作}
  \begin{itemize}
    \item 方向一：继续沿 carrier seam 把 block-aligned segmented path 推向 connector-backed、exact token-level 的 materialization path。
    \item 方向二：做更温和的参数扫描，明确 \texttt{partial\_reuse} 的 guardrail 何时应保留 \texttt{full\_reuse}/\texttt{recompute}。
    \item 方向三：若环境允许，接入显式 \texttt{kv\_transfer\_config} 与 connector-backed path，验证 transfer 成本是否能被控制策略真正利用。
  \end{itemize}

  \vspace{0.6em}
  \begin{block}{答辩时最重要的一句话}
    这项工作的难点不是“找重叠”，而是\alert{把有价值的重叠以正确代价兑现出来}。
  \end{block}
\end{frame}

\begin{frame}{总结}
  \begin{enumerate}
    \item arrival-time KV materialization 应被建模为三动作控制问题，而不是默认“有reuse就直接用”。
    \item offline 结果已经证明这个决策面有研究价值。
    \item 最新真实实验说明：把 carrier seam 推进到 segmented tail path 后，旧 tuned 的负结果被显著拉回，但不同 workload 对 baseline/tuned guardrail 的偏好并不相同。
    \item 因此后续工作的重点仍是\alert{runtime realization seam + 温和guardrail}，并以 workload-dependent 的方式陈述 live 证据，而不是把它写成统一正收益。
  \end{enumerate}
\end{frame}
