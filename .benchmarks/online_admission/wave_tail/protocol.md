# Is there an action crossover in the slow requests that determine p95?

Use only the 4,891 and 8,544 discovery fixtures, unchanged FP32 output head, peer-aware selector, model weights, service flags, TP2, 240 MiB LMCache budget, 4,096 verified prefix, and 2,048 resident prefix. Reset and prime resident state before every target. Keep supplemental copy lanes idle. Every wave has four cache-isolated 4,097-token peer prompts generating 16 tokens and launching at 0/250/500/750 ms. Change only target offset, relative to the first peer: 20,125,230,270,375,480,520,625,730,770,875,980 ms, equally weighted. These cover entry, mid-gap, either side of subsequent arrivals, and drain. Record actual dispatch times; require within 15 ms of plan for target and peers. Verify real engine reads (2,048 or zero), computed work, and each target/peer output ID against the same service's cold 32/16-token references before interpreting times.

1. Map the phase distribution with one warm-up and six balanced full/local pairs per offset. An offset qualifies only if every stream and receipt in both arms passes, including warm-up. Report unsuccessful offsets and distinguish the qualified distribution from the full grid. For each arm calculate linearly interpolated pooled p95 on the equally weighted qualified offsets. Include both observations bracketing p95 and all slower observations in that arm's tail. Freeze the static per-prompt 250 ms gate to the arm with lower p95 in this calibration (full on ties). At 2,048 external tokens the equivalent thresholds are 2,048 and 2,176.
2. Independently collect new repetitions in the same screening service for the union of offsets found in either arm's tail. One warm-up plus six counterbalanced pairs per candidate. A winner requires all six paired target-TTFT differences to agree in direction and all token/counter and arrival checks to pass. Promote only when at least two offsets from the same calibrated gate tail verify opposite winners. Report the other forced arm's tail as a sensitivity check. This rule avoids comparing a policy-specific slow request to an unrelated fast request. Pairing replays comparable phase and cache state, not the exact device schedule.
3. If promoted, compare the frozen selector with the calibrated gate on the complete qualified offset distribution, with four new engine/cache lifecycles. Within each lifecycle run one warm-up and eight pairs per phase, interleaving and counterbalancing order. Both arms share estimator history within a lifecycle. Every target and peer must match cold token-for-token. Use paired log ratios of per-lifecycle p95s for target TTFT and TPOT of peers actually co-scheduled with the target. Require both upper ends of two-sided 95% Student intervals (df=3) to meet TTFT <= -5% and peer TPOT <= +5%. No reserved requests.
