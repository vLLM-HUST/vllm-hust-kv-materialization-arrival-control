# Discovery-only test of within-load action reversal

Freeze the FP32-head serving build, peer-aware two-action selector, model, 240 MiB LMCache budget and scheduler of the repaired 7,742-token run. Use the 4,891-, 8,544- and 12,553-token discovery fixtures from distinct trajectories. Each prompt gets a separate engine and LMCache. Every target starts with exactly 2,048 local and 2,048 additional verified tokens. Reset APC and re-prime it for every request. Cold target (32 tokens) and cold peer (16 tokens) references are regenerated in each service lifecycle. Four cache-isolated peers use the same prompt's first 4,097 tokens. Record every ID, read receipt, prefill chunk, batch membership, and streaming time.

* Arrival sweep. Copy lanes idle. Four open-loop arrivals spaced 250 or 65 ms. At each spacing the first peer arrives either 1,800 ms after the target or 20 ms before it. Keep number of peers, spacing, input and output work identical in each phase pair.
* Transfer sweep. Keep peer arrivals fixed at -20, 230, 480 and 730 ms. Run one 450 ms pinned-host H2D burst on a dedicated stream per rank, medium (32 MiB batches with 3 ms pause) or high (back-to-back). Start 1,800 ms after or 100 ms before the target. Verify positive bytes on both ranks in both phases, and first-token interval intersection on both ranks exclusively in the early-burst phase. Intersecting batches count full batch bytes, not byte-exact overlap.
* Screening. Per cell, run one warm-up pair per phase then six counterbalanced full/local pairs per phase. Promote a cell only with exact outputs and correct exposure in all rows including warm-up, plus opposite strict signs in every one of the six paired target TTFT differences in the two phases (two-sided exact sign test p=0.03125 per phase, descriptive, no multiplicity correction). This tests target action ordering within one offered-load cell. It does not establish a joint tail-latency win. Calibrate the per-prompt, per-cell static gate to the forced endpoint with the smaller pooled timing p95 target TTFT over equally weighted phases (2,048 threshold for full, 2,176 for local). Freeze thresholds before confirmation.
* Confirmation. For every promoted cell, start four new engine and cache lifecycles per prompt; within each lifecycle pair the frozen selector and calibrated gate in counterbalanced order. One warm-up then eight pairs per phase. Require correct build, all target/peer tokens and exposure in every row. Use interpolated p95 across 16 targets per arm per lifecycle and across TPOTs of peers actually co-scheduled with the target. Peer TPOT = (last token time - first token time)/15. Also report co-batched peer counts and all-peer p95. Use paired lifecycle log ratios and two-sided Student-t intervals (df=3). Both upper bounds must satisfy target TTFT <= -5% and co-batched TPOT <= +5%. A correctness failure disqualifies the affected cell from a four-block performance claim. The held-out split stays sealed.
